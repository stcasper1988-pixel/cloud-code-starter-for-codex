# 4 запрета безопасности

**Когда брать:** сразу после `02-hooks.md`, обязательно перед включением режима полного доступа.
**Что делает:** блокирует 4 опасных типа команд через hook `PreToolUse` в `.codex/hooks.json`. Даже если ты случайно скажешь «удали всё» - Codex остановится до выполнения команды.
**Результат:** `.codex/hooks.json` с `PreToolUse` и policy script в `.codex/hooks/`.

## Что именно запрещаем

| Команда | Почему опасно |
|---|---|
| `rm -rf` и массовое удаление | Можно случайно стереть диск |
| `curl` + `export` переменных | Утечка секретов наружу |
| Чтение `.env` целиком | API-ключи и пароли попадают в транскрипт |
| `wget` с подставленными переменными | Экспорт данных наружу |

## Промпт

```prompt
Настрой мне в `.codex/hooks.json` правила безопасности. ЗАПРЕТИ:

1. Команды вида `rm -rf` и любое массовое удаление файлов или папок без явного подтверждения от меня.
2. Связку `export` + `curl` - любую отправку переменных окружения наружу через curl.
3. Чтение файлов .env и любых файлов с секретами, ключами, паролями (читать .env можно только через grep по конкретной переменной).
4. `wget` с подставленными переменными - любую отправку моих данных наружу через wget.

Используй `PreToolUse` hook Codex. Возьми конфигурацию из `templates/codex-hooks.json.example`, а scripts из `templates/codex-hooks/` скопируй в `.codex/hooks/`. Не замещай правила текстовой инструкцией: policy script должен возвращать Codex решение `deny` до запуска опасной команды.

Перед изменением - покажи текущий файл. После изменения - покажи итоговый `.codex/hooks.json` и policy script для моей ОС, затем объясни каждое правило одной строкой. Если Codex ещё не доверяет project-local hooks, проведи меня через `/hooks`; не включай режим полного доступа.
```

## Проверка

Попроси Codex выполнить `rm -rf tmp/` в тестовой папке - он должен остановиться и показать причину блокировки, не выполняя команду.

Попроси прочитать `.env` - он должен отказаться или использовать `grep`.
